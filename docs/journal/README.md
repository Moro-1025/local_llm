# 学習ジャーナル

このフォルダは「後から見返して、何をしたか・なぜそうしたか・どう確かめるか」が分かるための記録。
仕様書(external-spec / internal-spec)は「今どうなっているか」を書くが、ジャーナルは「どう辿ってきたか」を書く。
前提知識がない人が読む想定なので、専門用語は初出で 1 行説明を付ける。

## 一覧

| Phase | ファイル | 内容 |
| --- | --- | --- |
| 0〜2 | [phase-0-2.md](phase-0-2.md) | 土台、CLI、Web UI(振り返りとしてまとめ) |
| 3 | phase-3.md | RAG |

| 5 | phase-5.md | LoRA ファインチューニング(WSL) |
| 6 | phase-6.md | 評価・計測・公開 |

## 各 Phase のテンプレート

```markdown
# Phase N: タイトル

## この Phase で作ったもの(1 分で)
3〜5 行。図があれば 1 つ。

## なぜこの Phase が必要か
前の Phase の何が足りなかったか。次の Phase に何を渡すか。

## 用語
| 用語 | 1 行説明 |

## やったことの流れ
時系列で。判断に迷った点と、選んだ理由を必ず書く(例: 「ベクトル DB を入れなかった。理由は…」)。

## 動かし方
コマンドを順番に。期待する出力を 1 行添える。

## どう確かめたか(証拠)
Completion Report(docs/harness/reports/phase-N.md)への参照と、要点の抜粋。
「テストが通った」ではなく「このコマンドを打つとこう出る」の形で。

## うまくいかなかったこと・やり直したこと
失敗も記録する。後で同じ穴に落ちないため。

## 次の Phase への引き継ぎ
未完了、残存リスク、次に使うファイル。

## 参考リンク
```

## 書き方の約束

- 1 段落 3 行まで。長くなるなら見出しを切る。
- 数値(件数、tok/s、VRAM)は表に。
- コマンドは必ずコードブロックに。
- 「〜はず」「〜と思う」は書かない。確認していないことは「未確認」と書く。
